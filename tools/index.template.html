How they’re made

The viral code-rendered work of autumn 2026 isn’t generated video. It’s code that paints frames, and it follows the same workflow every time. Every piece here does too. The research behind them is in the research notes, and all the code is on GitHub.

  1. Storyboard first

    Shots, timings, easing and palette are fixed before any drawing code. The films keep their storyboards as tables; the intro keeps its song as one.

  2. Frames are functions of time

    The same t always paints the same frame. Randomness is seeded and simulations replay from a seed, so any moment can be scrubbed to, tested or re-rendered.

  3. Check contact sheets

    A headless browser calls __seek(t) at chosen moments, on the real GPU, and saves images. Score them, list the three worst flaws, fix, render again.

  4. Capture and encode

    Independent frames render in parallel and ffmpeg stitches them, with audio rendered offline from the same synth code. The previews on this page were made the same way.
